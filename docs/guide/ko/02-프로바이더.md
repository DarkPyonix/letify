# 2️⃣ 프로바이더와 계정

## 모델

프로바이더 객체는 **하나의 인프라 종류에 있는 하나의 계정**입니다. 설정 파일에 한 번 선언하고 alias로 꺼내 씁니다.

```python
let = letify.Launcher()

colab = let.providers.colab_a      # 구글 계정 하나
lab   = let.providers.lab_a100     # 머신 하나
here  = let.providers.local        # 항상 존재, 선언 불필요
```

GPU는 프로바이더의 속성이고, 그 값이 선언에 필요한 모든 것을 담고 있습니다.

```python
@let.function(device=colab.G4, host="remote")
def train(lr): ...
```

`colab.G4` 하나에 프로바이더, 계정, GPU, CPU 배치가 들어 있습니다. 이 넷은 하나의 결정이라서 하나의 인자입니다.

## 설정이 있는 곳

letify는 상태를 역할이 다른 `.letify` 디렉터리 두 곳에 둡니다.

| 경로 | 담는 것 | Git 추적? |
|---|---|---|
| `~/.letify/config.toml` | 이 머신의 모든 계정: kind와 접속 정보, 비밀은 없음 | 아니오, 저장소 밖입니다 |
| `~/.letify/accounts/<alias>/` | 그 계정의 자격 증명, 소유자만 접근 | 아니오 |
| `<project>/.letify/config.toml` | 프로젝트 기본값, 프로젝트가 쓰는 계정의 alias | 예 |

홈 파일은 이 머신에 있는 계정의 목록입니다. 프로젝트 파일은 그중에서 고릅니다. 계정은 다음 중 하나일 때만 프로젝트에서 쓸 수 있습니다.

1. 프로젝트 파일이 그 이름을 적었습니다. 빈 테이블로 충분합니다.
2. 홈 항목에 `global = true`가 있습니다.
3. `local`입니다. 항상 쓸 수 있습니다.

```toml
# 프로젝트의 .letify/config.toml, 커밋됨
[colab_a]         # 홈 계정 colab_a를 설정 그대로 사용
[lab_a100]
```

프로젝트 테이블에 적은 필드는 홈 항목의 같은 필드를 덮어씁니다. 다른 사람은 저장소를 받아 거기 적힌 alias에 대해 `letify login`을 실행하면 됩니다.

## 비밀

자격 증명은 어느 `config.toml`에도 들어가지 않습니다. `letify login`이 묻고 저장합니다.

```bash
letify login elice elice_a100      # ~/.letify/accounts/elice_a100/access_token에 기록
letify logout elice_a100           # 계정을 지우고 그 디렉터리도 삭제
```

`access_token` 같은 필드는 다음 순서로 해소됩니다.

1. `access_token_env`가 가리키는 환경 변수.
2. 파일 `~/.letify/accounts/<alias>/access_token`. 권한 0600으로 만들어집니다.
3. 홈 항목의 리터럴 값. 비밀이 아닌 기본값에만 씁니다.

```toml
[elice_a100]
kind = "elice"
access_token_env = "ELICE_ACCESS_TOKEN"        # 선택, 저장된 파일보다 우선
```

OS 키링은 쓰지 않습니다.

## 📓 Colab

```toml
[colab_a]
kind = "colab"
account = "you@example.com"
```

공식 Colab CLI를 쓰므로 터널이 필요 없고 약관 위험도 없습니다. 세션은 `colab new`로 만들고 `colab stop`으로 내리며, 백그라운드 데몬이 브라우저 탭 없이도 런타임이 유휴 종료되는 것을 막아줍니다.

| | |
|---|---|
| GPU | `T4`, `L4`, `G4`, `A100`, `H100`, TPU는 `v5e1`, `v6e1` |
| `G4`는 | RTX PRO 6000 Blackwell, 96GB. `RTX_PRO_6000`도 alias로 인정 |
| 저장소 | **휘발성.** 런타임을 바꾸면 새 머신에 빈 디스크입니다 |
| 실행 방식 | 함수 전송만 |
| 캐시 백엔드 | Google Cloud Storage |

두 가지를 알아두세요. GPU는 Pro 또는 Pro+ 권한이 필요하고, 원격 제어 기능은 컴퓨트 유닛 잔액이 양수인 동안 허용됩니다. 잔액이 소진되면 계정이 무료 티어 정책으로 돌아가고, 그 정책은 이 기능들을 금지합니다.

여기서 `host="local"`은 예외를 던집니다. 제어 경로가 구글 프론트엔드를 거쳐서 한국에서 왕복이 150~200ms이고, 그러면 파인튜닝은 절반, 추론은 몇 퍼센트만 남습니다. 예외 메시지에 그 내용이 그대로 들어 있습니다.

## 🐚 Shell, 연구실이나 학교 서버용

```toml
[lab_a100]
kind = "shell"
address = "gpu.lab.example.edu"
user = "researcher"
key = "~/.ssh/id_ed25519"
persistent = true
```

| 옵션 | 역할 |
|---|---|
| `address`, `user`, `port`, `key` | 표준 SSH 접속 정보 |
| `jump` | 점프 호스트, `ssh -J`로 전달 |
| `persistent` | 세션 사이에 디스크가 유지된다고 선언 |
| `gpus` | 목록. 탐색 시 접속을 건너뜁니다 |
| `port_command` | 현재 포트를 출력하는 명령. 포트가 바뀌는 호스트용 |
| `store` | 캐시 백엔드 덮어쓰기 |

**저장소 수명의 기본값은 휘발성이고, 일부러 비관적으로 잡았습니다.** 실제로는 디스크가 남는데 휘발성으로 가정하면 시간만 더 들고 작업은 성공합니다. 반대로 남지 않는데 persistent로 가정하면 바로 실패합니다.

머신이 홈 디렉터리를 유지한다는 것을 확인하면 `persistent = true`를 넣으세요. 연구실 서버라면 보통 그렇습니다. 그러면 기본 실행 방식이 함수 전송으로 바뀝니다.

`gpus`를 선언하면 import 시점에 SSH가 붙지 않습니다.

```toml
gpus = ["A100", "A100", "A100", "A100"]
```

## 🕳️ Tunnel, NAT 뒤의 머신용

인바운드 연결을 받을 수 없는 머신용입니다. 터널은 경로만 만들고, 작업은 여전히 SSH가 합니다.

```toml
[home_box]
kind = "tunnel"
transport = "tailscale"
address = "home-box"               # Tailscale 머신 이름
user = "researcher"
auth_key_env = "TS_AUTHKEY"
mtu = 1280
persistent = true
```

Tailscale이 기본값인 이유는 자체 서버가 필요 없고, auth key로 프롬프트 없이 인증되며, 임의의 TCP 포트를 그대로 통과시키기 때문입니다. UDP가 막히면 TCP 443으로 중계하는데, 끊기지는 않지만 느려집니다.

망에서 UDP를 막고 중계가 너무 느리면 전송 수단을 바꾸세요.

```toml
transport = "frp"
frp_config = "~/.config/frp/frpc.toml"
```

> ⚠️ **MTU를 낮게 두세요.** 이 계열의 메시 VPN은 대략 1400을 넘으면 같은 증상을 보입니다. 터널은 붙고 짧은 명령은 되는데 대용량 전송만 조용히 멈춥니다. 1280은 항상 동작합니다.

더 단순한 경로를 먼저 시도하세요. 직접 주소, 그다음 점프 호스트, 그다음 터널입니다. 학교 머신은 앞의 두 개가 되는 경우가 많습니다. 상세한 측정치는 [docs/NETWORK.md](../../NETWORK.md)에 있습니다.

## ☁️ Modal

```toml
[modal_lab]
kind = "modal"
```

계정마다 한 번 로그인합니다.

```bash
letify login modal modal_lab
```

letify가 선택 사항인 워크스페이스 이름을 묻고, uv로 Modal의 `modal token new`를 실행합니다. 출력된 링크를 브라우저에서 승인하세요. 토큰은 `~/.letify/accounts/modal_lab/modal.toml`에 저장되므로 한 머신에 Modal 계정 두 개가 공존할 수 있습니다. `modal`을 `PATH`나 프로젝트 `.venv`에 직접 설치할 필요가 없습니다. 필요한 것은 uv뿐입니다.

Modal 볼륨은 컨테이너 밖에서 마운트되므로 저장소가 persistent이고, 기본이 함수 전송이며 별도 캐시 계층이 필요 없습니다.

`host="local"`은 예외를 던집니다. Modal은 컨테이너로 들어가는 함수 호출을 제공하고, CUDA 호출을 중계할 장치를 제공하지 않습니다.

Modal 클라이언트는 letify가 첫 호출 때 띄우는 작은 어댑터 프로세스 안에서, Modal을 `>=1.0,<2`로 고정한 별도 uv 환경으로 실행됩니다. 처음 띄울 때 Modal을 uv 캐시에 내려받습니다. 셸의 `MODAL_TOKEN_ID`, `MODAL_TOKEN_SECRET`에 든 토큰은 무시됩니다. 어느 계정으로 동작할지는 그 계정의 `modal.toml`이 정합니다.

## 🇰🇷 Elice

```toml
[elice_a100]
kind = "elice"
zone_id = "00000000-0000-0000-0000-000000000000"
machine_id = "00000000-0000-0000-0000-000000000000"
address = "..."
user = "elicer"
key = "~/.ssh/elice.pem"
access_token_env = "ELICE_ACCESS_TOKEN"
```

공개 REST API가 있는 Elice Cloud Infrastructure를 대상으로 합니다. letify는 allocation을 만들고 지우는 방식으로 머신을 켜고 끄는데, 이것이 세션과 정확히 대응하므로 호출의 수명이 엘리스의 수명 주기를 그대로 따릅니다.

**letify는 머신을 만들지 않습니다.** 가상 머신은 콘솔이나 Terraform으로 한 번 선언하고 그 id를 `machine_id`에 넣으세요. letify는 할당과 반납만 합니다.

비용 두 가지를 기억하세요. 컴퓨트는 할당 중 초 단위로 과금되고, 블록 스토리지는 머신이 정지된 동안에도 계속 과금됩니다. 잊은 머신은 allocation이 없어도 돈이 나갑니다.

엘리스의 다른 제품인 Run Box는 콘솔로만 제어되고 API가 없습니다. 그래도 터널 주소와 포트를 적어 평범한 `shell`로 선언하면 쓸 수 있습니다.

## 💻 Local

항상 있고 선언이 필요 없습니다. 전송 없이 이 머신의 서브프로세스에서 선언된 함수를 실행합니다.

```python
here = let.providers.local
here.CPU                      # 항상 있음
here.GeForce_RTX_4050         # nvidia-smi가 보고하는 것
```

두 가지 용도가 있습니다. GPU가 있으면 다른 것과 같은 선언으로 그걸 씁니다. 없어도 테스트가 목 객체 대신 실제 경로를 지나갑니다.

## 🔀 계정 여러 개

설정 항목 하나가 계정 하나이고, 같은 종류를 여러 개 둘 수 있습니다. 동시 세션을 늘리는 방법입니다.

```toml
[colab_a]
kind = "colab"
account = "first@example.com"

[colab_b]
kind = "colab"
account = "second@example.com"
```

```python
a = let.providers.colab_a
b = let.providers.colab_b

@let.function(device=a.G4, host="remote")
def train(lr): ...

@let.function(device=b.L4, host="remote")
def evaluate(ckpt): ...
```

한 계정에서 학습하고 다른 계정에서 평가하는 구성이 흔합니다. 긴 작업이 짧은 확인을 막지 않기 때문입니다.

## 🎲 프로바이더를 고르지 않기

```python
@let.function(device=let.providers.any.A100, host="remote")
def train(lr): ...
```

`A100`을 등록한 첫 프로바이더를 고릅니다. 우선순위는 설정 파일에 적힌 순서이니, 선호하는 프로바이더를 앞에 두세요.

## 🔍 살펴보기

```python
let.providers.aliases          # ['colab_a', 'lab_a100', 'local']
let.providers.devices             # 프로바이더별 GPU
let.providers.active           # 지금 런타임을 들고 있는 프로바이더
let.providers.colab_a.instances
let.providers.lab_a100.refresh()   # 머신에 다시 물어보기
```

`let.providers.active`는 지금 돈이 나가고 있는지에 대한 가장 빠른 답입니다.

```bash
letify providers
letify devices
letify status
letify check lab_a100
```
