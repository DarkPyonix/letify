# 7️⃣ 문제 해결

> letify가 던지는 각 예외의 실제 의미와 대처.

[← 비용 관리](06-비용.md) · [가이드](README.md)

---

## 예외 읽는 법

letify는 실패를 두 종류로 나누고, 그 구분이 재시도가 도움이 되는지를 결정합니다.

| 종류 | 예외 | 재시도? |
|---|---|---|
| 인프라가 잘못됨 | `RuntimeFailure`, `RuntimeLost`, `ProtocolError` | 예, 새 런타임에서 |
| 내 코드가 예외를 던짐 | `RemoteError` | 아니오, 재시도하면 같은 결과 |
| 불가능한 것을 요청함 | `ConfigError`, `UnsupportedMode`, `UnknownProvider`, `UnknownInstance`, `InsufficientDevices` | 아니오 |
| 의존성이나 설정 누락 | `ProviderUnavailable` | 아니오 |

---

## `NotRunning`

이 예외는 더 이상 없습니다. 세션에 스코프가 필요하지 않습니다. 호출이 세션을 시작하고 끝내니
밖에 있을 것 자체가 없습니다.

`with let.run():`으로 호출을 감싼 예전 예제를 보고 있다면, 감싼 줄을 지우고 본문을 한 단계
왼쪽으로 옮기면 됩니다. 그 호출들이 의도적으로 세션을 공유하고 있었다면
`with let.keep_alive():`로 감싸세요.

---

## `ProviderUnavailable`

```
provider 'modal' is unavailable: uv was not found.
Install uv, or set the UV environment variable to its path.
```

letify는 프로바이더 도구를 uv로 실행합니다. `UV`를 먼저 보고, 다음에 `PATH`를 봅니다. 메시지가 누락된 설정을 말한다면 그 필드를 설정에 추가하세요.

```
provider 'elice' is unavailable: elice_a100 needs an access token. Run 'letify login
elice elice_a100', which keeps it in ~/.letify/accounts/elice_a100/, or set access_token_env
```

---

## `ConfigError`

**하이픈이 들어간 alias.**

```
.letify/config.toml: alias 'colab-a' is not a Python identifier, so
let.providers.colab-a cannot work. Try 'colab_a'.
```

프로바이더를 속성으로 접근하므로 alias는 유효한 식별자여야 합니다.

**예약된 alias.**

```
.letify/config.toml: 'any' is reserved. Pick another alias, because let.providers.any
already means something else.
```

`any`, `devices`, `active`는 이미 쓰이고 있습니다.

**이 머신에 없는 프로젝트 alias.**

```
.letify/config.toml: 'lab_a100' names an account that ~/.letify/config.toml does not
have. Run 'letify login <kind> lab_a100' to declare it on this machine, or give the
table a 'kind' to declare it here.
```

저장소가 아직 로그인하지 않은 계정을 적고 있습니다. 메시지가 알려주는 명령을 실행하세요.

**kind 누락.** 모든 항목에 `kind`가 필요합니다. 유효한 값은 `local`, `colab`, `modal`, `shell`, `ssh`, `tunnel`, `elice`입니다.

---

## `UnknownProvider`와 `UnknownInstance`

```
no provider is declared under 'colab_b'. Declared: colab_a, lab_a100, local.
Name it in .letify/config.toml, and declare the account in ~/.letify/config.toml.
```

`~/.letify/config.toml`의 계정은 프로젝트의 `.letify/config.toml`이 이름을 적었거나 홈 항목에 `global = true`가 있을 때만 그 프로젝트에 존재합니다.

```
colab_a does not offer 'B200'. Available: A100, G4, H100, L4, T4, v5e1, v6e1
```

두 메시지 모두 존재하는 것을 나열합니다. `letify providers`와 `letify devices`가 같은 내용을 셸에서 보여줍니다.

---

## `UnsupportedMode`

```
Colab does not support host='local'. Forwarding CUDA calls over the Colab control
path costs one round trip of about 150 ms per host synchronization, which leaves
roughly half the throughput for fine-tuning and a few percent for token by token
decoding. Use host='remote' so the loop runs inside the runtime.
```

letify가 느린 경로를 조용히 타는 것을 거부하는 것입니다. `host="remote"`를 쓰거나, 그 작업을 빠른 경로가 있는 프로바이더로 옮기세요. `Shell`, `Tunnel`, `Elice`가 해당됩니다. [실행 방식](03-실행-방식.md)을 보세요.

---

## `InsufficientDevices`

호출에 필요한 카드를 할당할 수 없고 실행 중인 무엇도 카드를 풀어주지 않을 때, letify는 기다리는 대신 이 예외를 던집니다. 재시도해도 같은 인벤토리에 같은 카드를 요청하므로 재시도하지 않습니다.

**계정이 선언한 것보다 많은 카드.**

```
<Instance lab_a100:A100 host=remote> asks for 8 A100 but lab_a100 declares 4, so it
can never be allocated. Ask for fewer, or declare more in the account's devices table.
```

**`keep_alive` 블록의 유휴 세션이 카드를 잡고 있음.**

```
every G4 on colab_a is held by a session that is idle but kept by let.keep_alive() (...),
and this call needs a session with a different environment. Nothing running would free
a card. Make the call outside the block, or give colab_a more G4 in its devices table.
```

**다른 프로세스가 카드를 쓰고 있음.**

```
no A100 on lab_a100 can be allocated: the cards it may use are taken by another process,
and letify cannot know when that process ends.
```

공유 머신이라면 보통 동료가 그 카드로 계산 중이라는 뜻입니다. `letify utilization`으로 확인한 뒤 나중에 다시 시도하거나, devices 테이블의 `indices`를 좁히세요.

---

## `RemoteError`

내 함수가 원격 머신에서 예외를 던졌습니다. 원격 트레이스백이 붙어 있습니다.

```python
try:
    train(lr=1e-4)
except letify.RemoteError as exc:
    print(exc.remote_traceback)
```

재시도하지 않습니다. 재시도하면 같은 결과가 나오기 때문입니다. 가능하면 로컬에서 먼저 디버깅하세요.

```python
train.local(lr=1e-4)      # 이 프로세스에서 본문 실행
```

또는 같은 함수를 `Local` 프로바이더로 선언해서 원격 머신 없이 전체 경로를 지나가게 하세요.

**알아둘 만한 흔한 원인들.** 로컬에는 있는데 lock 파일에 없는 import는 `Env.pip_install`이나 lock 파일 갱신으로 해결됩니다. 메모리 부족은 PyTorch가 예외를 던졌으면 `RemoteError`로, 프로세스가 죽었으면 `ProtocolError`로 나타납니다. 내 머신에는 있고 런타임에는 없는 경로는 보통 볼륨에 있어야 할 데이터를 뜻합니다.

---

## `ProtocolError`

```
the runtime produced no result marker, so the process died before it finished.
The usual causes are an out of memory kill, a preempted session, or a crash
below Python.
--- last remote output ---
...
```

원격 프로세스가 결과를 돌려주지 않고 죽었습니다. 출력의 마지막 부분이 포함되는데, 보통 그것으로 어느 경우인지 알 수 있습니다.

| 원인 | 신호 | 대처 |
|---|---|---|
| 메모리 부족으로 강제 종료 | 파이썬 트레이스백 없이 스텝 중간에 출력이 끊김 | 배치를 줄이거나 gradient checkpointing을 켜거나 더 큰 카드로 |
| 세션 선점 | 특별할 것 없는 지점에서 발생 | 볼륨에 체크포인트를 써서 재실행이 이어지게 |
| 파이썬 아래에서의 크래시 | 마지막 출력에 CUDA나 드라이버 메시지 | 보통 환경의 버전 불일치 |

세션이 잘못한 것이므로 letify가 런타임을 버리고 기본 1회 재시도합니다.

---

## `RuntimeFailure`와 `RuntimeLost`

```
train failed after 2 attempt(s) on <Instance colab_a:G4 host=remote>: ...
```

세션에 닿지 못했거나 명령이 실패했습니다. `RuntimeFailure`는 명령과 원격 stderr를 담고 있습니다.

```python
except letify.RuntimeFailure as exc:
    print(exc.command)
    print(exc.stderr)
```

**Colab이라면:** `colab sessions`로 CLI가 단독으로 동작하는지 확인하세요. 컴퓨트 유닛 잔액이 양수인지 확인하세요. 잔액이 소진되면 계정이 무료 티어 정책으로 돌아가고 그 정책은 letify가 쓰는 기능을 금지합니다. GPU가 그냥 없을 수도 있습니다. 보장되지 않는 사항이고, 블랙웰 물량이 빠듯해서 `G4`는 더 그렇습니다.

**Shell 머신이라면:** `letify check <alias>`를 해보세요. 그다음 SSH 명령을 직접 실행해보세요. 재시작할 때 포트가 바뀌는 호스트는 설정에 `port_command`가 필요합니다.

**Tunnel이라면:** `let.providers.<alias>.diagnose()`가 전송 수단, MTU, 그리고 경로가 중계인지를 보고합니다.

---

## `letify is not installed in this runtime's environment`

```
RemoteError: letify is not installed in this runtime's environment, so the call, which
refers to letify (for example through letify.session_cache), cannot be loaded.
```

선언된 함수 본문이 letify를 참조하는데(대개 `letify.session_cache`를 통해서), 런타임 환경에 letify가 없습니다. `uv add letify`를 실행해서 `uv.lock`이 letify를 런타임까지 가져가게 하세요.

## 세션 캐시가 호출할 때마다 다시 만들어집니다

`letify.session_cache`는 세션이 끝날 때까지 값을 유지합니다. `with let.keep_alive():` 밖에서는 호출마다 세션이 끝나므로, 호출들을 이 블록으로 감싸세요. Colab `channel = "exec"` 같은 일회성 채널에서는 호출마다 새 프로세스라서 호출 사이에 아무것도 남지 않습니다. 동시에 실행되는 호출이 서로 다른 세션에 있으면 각자 값을 만들며, 이는 정상입니다.

## 고장이 아니라 느린 경우

### 세션 시작이 20분 걸립니다

볼륨을 붙이지 않았습니다. 붙이세요.

```python
cache = colab.volume("hf-cache")

@let.function(device=colab.G4, host="remote", volumes=[cache])
def train(lr): ...
```

런타임 옆 버킷에서 20GB를 받으면 40~60초이고, 먼 원본에서 받으면 27분입니다. [환경과 데이터](04-환경과-데이터.md)를 보세요.

### 같은 코드를 직접 돌릴 때보다 훨씬 느립니다

`host="local"`이면 CUDA 호출을 중계하고 있고 동기화마다 왕복을 내고 있습니다. 두 항을 모두 재세요.

```bash
letify probe gpu.lab.example.edu
```

```python
import torch
torch.cuda.set_sync_debug_mode("warn")     # 한 스텝의 경고 개수를 셉니다
```

그다음 `효율 = T / (T + k × RTT)`입니다. 결과가 나쁘면 `host="remote"`로 바꾸거나 `k`를 줄이세요. [실행 방식](03-실행-방식.md)을 보세요.

`host="remote"`인데도 느리면 루프 자체가 느린 것입니다. 스텝마다 letify 오버헤드 없이 원격에서 돌고 있으니, 로컬에서 하듯 프로파일링하세요.

### 터널에서 짧은 명령은 되는데 대용량 전송이 멈춥니다

MTU 증상이고, 터널에서 가장 흔한 문제입니다. 낮추세요.

```toml
[home_box]
kind = "tunnel"
mtu = 1280
```

그다음 경로가 중계인지 확인하세요. 중계된 Tailscale 경로는 대륙 간에서 2.2Mbit/s까지 측정된 사례가 있습니다.

```python
let.providers.home_box.diagnose()
```

중계이고 망에서 UDP가 막혀 있으면 TLS 443을 쓰는 `transport = "frp"`로 바꾸세요. [docs/NETWORK.md](../../NETWORK.md)를 보세요.

### 모은 호출이 병렬로 돌지 않습니다

두 가지를 확인하세요. 프로바이더 항목이 무엇을 가졌다고 선언했는지, 그리고 실제로 세션이 몇 개 떴는지입니다.

```python
print(len(let.pool.live))
```

요청한 것보다 적게 떴다면 프로바이더가 거부한 것입니다. Colab의 그 한도는 문서화되어 있지 않고 등급과 크레딧 잔액과 수요에 따라 바뀝니다. 싼 `L4` 세션으로 찾아보세요. [동시 실행과 용량](05-동시-실행.md)을 보세요.

## 버그가 아닌 것들

**프로바이더를 하나도 설치하지 않아도 `import letify`가 됩니다.** 설계입니다. 패키지가 없는 프로바이더는 사용 불가라고 알리고 나머지는 동작합니다.

**`let.providers.devices`에서 한 프로바이더가 `unavailable: ...`로 나옵니다.** 이것도 설계입니다. 하나가 깨졌다고 나머지가 안 보이면 안 됩니다.

**GPU 이름이 정규화됩니다.** `NVIDIA RTX PRO 6000 Blackwell`은 속성으로 쓰려고 `RTX_PRO_6000`이 됩니다. Colab에서는 같은 카드가 CLI 표기를 따라 `G4`이고, `RTX_PRO_6000`도 alias로 인정합니다.

**디스크가 유지되는 머신인데도 Shell 프로바이더가 기본적으로 휘발성입니다.** 의도적입니다. 휘발성으로 잘못 짚으면 시간이 들고, persistent로 잘못 짚으면 실패합니다. 확인한 뒤에 `persistent = true`를 선언하세요.

## 버그 신고

다음 출력을 포함해주세요.

```bash
letify --version
letify providers
letify devices
```

그리고 전체 트레이스백입니다. `RemoteError`라면 `exc.remote_traceback`을, `RuntimeFailure`라면 `exc.command`와 `exc.stderr`를 넣어주세요. 계정 이름과 주소는 가리고, 토큰은 절대 붙여넣지 마세요.
