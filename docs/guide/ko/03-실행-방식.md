# 3️⃣ 실행 방식 고르기

> 루프를 보낼지 CUDA 호출을 중계할지. 어느 쪽이 언제 이기는지, 계산식과 함께.

## 두 가지 방식

| | 📦 함수 전송 | 🔌 호출 중계 |
|---|---|---|
| 이렇게 씁니다 | `cpu="remote"` | `cpu="local"` |
| Python이 도는 곳 | 원격 머신 | 내 프로세스 |
| 데이터가 있어야 하는 곳 | 원격 머신 | 내 머신 |
| 네트워크를 지나는 것 | 함수, 한 번 | 모든 CUDA 호출 |
| 그 비용 | 전송 한 번 | 동기화마다 왕복 한 번 |

코드에는 이 이름이 나오지 않습니다. CPU 쪽 작업이 어디에 있는지만 말하면 letify가 방식을 고릅니다.

```python
@let.function(gpu=colab.G4)                    # 프로바이더 기본값
@let.function(gpu=lab.A100(cpu="remote"))      # 루프를 보냅니다
@let.function(gpu=lab.A100(cpu="local"))       # CUDA 호출을 중계합니다
```

## 계산식

```
효율 = T / (T + k × RTT)
```

- `T`는 스텝당 GPU 시간
- `k`는 그 스텝에서 호스트가 장치의 값을 읽어오는 횟수
- `RTT`는 네트워크 왕복

함수 전송은 루프를 원격에서 돌리니 그 읽기들이 거기서 로컬 호출이 되고 `k × RTT`가 사라집니다. 중계는 매번 그 값을 냅니다.

## 실제 숫자

RTX PRO 6000에 NVFP4, 마이크로스텝 0.5초, `k = 3`일 때입니다.

| 왕복 | 파인튜닝 | 추론, 배치 1 |
|---|---|---|
| 20ms | 89% | 초당 43토큰 |
| 150ms | **53%** | 초당 6.5토큰 |
| 450ms | 27% | 초당 2토큰 |

함수 전송은 저 왕복 전부에서 약 99%이고, 추론은 초당 수백 토큰입니다.

### 몸에 익혀둘 반직관적 사실 두 가지

**GPU가 빠를수록 중계가 불리합니다.** `T`는 줄어드는데 `RTT`는 그대로입니다. 같은 스텝이 L4 bf16에서는 1.8초라 80%가 나오고, RTX PRO 6000에서는 53%가 나옵니다.

**추론에서는 카드가 의미를 잃습니다.** 속도가 초당 약 `1000 / (k × RTT)` 토큰에서 막힙니다. 150ms에서는 L4와 RTX PRO 6000이 모두 초당 5~6토큰입니다. 이 방식에서는 빠른 카드에 돈을 더 내도 얻는 게 없습니다.

## `k`는 어디서 나오나

Hugging Face 학습 스텝은 기본 설정에서 `k ≈ 3`입니다.

| 동기화 | 빈도 | 이유 |
|---|---|---|
| `logging_nan_inf_filter` | 마이크로스텝마다 | `torch.isnan(loss)`를 파이썬 bool로 평가 |
| SDPA 어텐션 마스크 검사 | forward마다 | `torch.all(attention_mask == 1)`로 causal 경로 판단 |
| loss나 grad_norm 로깅 | 로깅 스텝마다 | `.item()` |
| GradScaler | fp16이면 스텝마다 | 무한대 검사 |

동기화를 강제하는 다른 것들도 있습니다. `nonzero()`, 불리언 마스크 인덱싱, `unique()`, 그리고 전문가별 토큰 수를 호스트로 읽어오는 MoE 라우팅입니다. 출력 크기를 호스트가 알아야 하는 연산은 모두 동기화입니다.

### 추측하지 말고 측정하세요

```python
import torch

torch.cuda.set_sync_debug_mode("warn")
# 실제 학습 스텝을 딱 한 번 돌리고 경고 개수를 셉니다
```

GPU가 어디 있는지와 무관하므로 Colab 런타임을 포함해 어떤 CUDA 장치에서도 잴 수 있습니다. `k`와 왕복을 둘 다 재면 계산식이 추정이 아니라 실제 답을 줍니다.

```bash
letify probe gpu.lab.example.edu     # 왕복과 중계 가능 여부
```

## `k`를 줄이기

중계가 본질적으로 53%인 것은 아닙니다. 그건 **기본 설정에서** 53%입니다. 아래 세 가지를 바꾸면 옵티마이저 스텝당 약 1회만 남아서 약 96%가 됩니다.

1. **NaN 필터 끄기.** `TrainingArguments`에 `logging_nan_inf_filter=False`.
2. **마스크 검사 없애기.** 고정 길이 packing을 쓰고 `attention_mask=None`을 넘겨서 마스크를 보지 않고 causal 경로를 타게 합니다.
3. **accumulation 경계에서 로깅.** `logging_steps`를 조정해 loss와 grad_norm을 마이크로스텝마다가 아니라 옵티마이저 스텝마다 읽게 합니다.

NaN 필터만 끄면 마스크 검사가 남아서 92%에서 멈춥니다.

이건 사용자의 학습 코드를 손보는 일이라 letify가 대신 해줄 수 없고, 그래서 기본값이 전송인 것입니다.

## 기본값이 정해지는 방식

**저장소가 먼저, 그다음 회선입니다.**

| 프로바이더 상태 | 기본값 | 방식 |
|---|---|---|
| persistent | `remote` | 전송 |
| ephemeral, 볼륨 붙음 | `remote` | 전송 |
| ephemeral, 볼륨 없음, 빠른 회선 | `local` | 중계 |
| ephemeral, 볼륨 없음, 느린 회선 | `remote` | 전송 |

논리는 이렇습니다. 저장소가 런타임보다 오래 살면 데이터와 환경이 이미 거기 있으니 루프를 보내는 게 자연스럽습니다. 아무것도 남지 않으면 상태를 내 머신에 두는 편이 매 세션 재구성을 피하고, 중계는 원격에 드라이버와 데몬만 있으면 되므로 새 머신에 요구하는 설정이 가장 적습니다.

실제로는 이렇습니다.

| 프로바이더 | 기본값 | 중계 가능? |
|---|---|---|
| `Local` | local | 해당 없음, 네트워크를 지나지 않습니다 |
| `Colab` | remote | ❌ 아니오, 왕복이 너무 깁니다 |
| `Modal` | remote | ❌ 아니오, 장치가 아니라 함수 호출을 제공합니다 |
| `Shell`, `Tunnel` | persistent나 볼륨이 없으면 local | ✅ 예 |
| `Elice` | remote | ✅ 예 |

## 조용한 폴백은 없습니다

```python
@let.function(gpu=colab.G4(cpu="local"))
def train(lr): ...
```

```
UnsupportedMode: Colab does not support cpu='local'. Forwarding CUDA calls over
the Colab control path costs one round trip of about 150 ms per host
synchronization, which leaves roughly half the throughput for fine-tuning and a
few percent for token by token decoding. Use cpu='remote' so the loop runs
inside the runtime.
```

letify는 느린 경로를 타는 대신 예외를 던집니다. 조용한 하향 조정은 네 배 느려진 실행을 미스터리로 만들고, 미스터리는 예외보다 비쌉니다.

## 실제로 고르는 기준

**루프를 보내세요.** 학습, 평가, 배치 추론, 그리고 통째로 넘길 수 있는 루프라면 전부 해당합니다. 사실상 거의 전부이고, 그래서 기본값입니다.

**호출을 중계하세요.** 코드가 대화형이고 사람 속도로 돌 때, 데이터가 내 머신에 있어야 할 때, 그리고 머신이 가까울 때입니다. 노트북에서 탐색하는 작업이 솔직한 사용 사례입니다. 셀당 20ms는 사람이 못 느끼고, 데이터는 이미 있는 자리에 그대로 있습니다.

**생성 루프는 절대 중계하지 마세요.** `generate` 호출 전체를 보내면 카드의 실제 속도가 나옵니다.

## 구현 상태에 대한 참고

함수 전송은 지금 동작합니다. 호출 중계는 현재 가능 여부 검사 단계입니다. `letify.remoting.probe()`가 L3 터널이 가능한지, 드라이버 shim이 있는지, 왕복이 얼마인지 보고하고, `require()`는 중계가 이득이 없을 때 예외를 던집니다. 중계 클라이언트 자체는 작성되지 않았습니다. [docs/SPEC.md](../../SPEC.md) 끝의 미구현 목록을 보세요.
