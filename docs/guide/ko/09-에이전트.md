# 9️⃣ letify 에이전트

> 공인 주소가 없는 머신에 SSH 서버도, letify가 운영하는 릴레이도 없이 닿는 방법입니다.

[← 릴리스](08-릴리스.md) · [가이드](README.md)

---

## 무엇에 쓰는가

`letify agent`는 들어오는 연결을 받을 수 없는 머신, 예를 들어 NAT 뒤의 연구실 서버를 위한 것입니다. 그 머신에서 `letify agent serve`를 실행하고, 내 머신을 한 번 페어링합니다. 그 뒤로는 시그널링 서비스를 거쳐 내 머신이 그 머신에 닿습니다. 시그널링 서비스는 두 머신 사이에서 서명된 메시지만 전달하는 작은 웹 서비스입니다.

에이전트에는 SSH 서버도 Tailcat도 필요 없습니다. letify가 운영하는 릴레이도 없습니다.

아래에서 쓰는 용어입니다.

- **에이전트**: 주소 없는 머신에서 계속 실행되는 `letify agent serve` 프로세스.
- **시그널링 서비스**: 양쪽이 접속하는 웹 서비스. 기본값은 `https://letify.darkpyonix.dev`입니다.
- **페어링**: 에이전트가 내 머신을 받아들이게 만드는 일회성 단계.
- **노드 id**: 머신의 키를 가리키는 64자리 16진수 이름. 머신마다 하나씩 있습니다.
- **토큰**: 페어링을 위해 `letify agent serve`가 출력하는 한 줄 문자열.

---

## 시작하기 전에

- 에이전트 머신에 letify가 설치되어 있습니다 (`uv add letify`).
- `letify-link` 바이너리가 있습니다. 플랫폼별 wheel에 들어 있습니다. 없으면 명령이 `letify-link is not in this wheel`로 실패합니다. 환경 변수 `LETIFY_LINK_BIN`으로 다른 실행 파일을 지정할 수 있습니다.
- 에이전트 머신에서 시그널링 서비스로 나가는 `https://` 연결이 가능합니다.
- 시그널링 서비스 URL은 따로 지정하지 않으면 `https://letify.darkpyonix.dev`입니다. 우선순위는 다음과 같습니다.
  1. `letify agent serve --signal <URL>`
  2. 환경 변수 `LETIFY_SIGNAL_URL`
  3. `~/.letify/agent/config.toml`의 `signal`
  4. 기본값

  URL은 `https://`여야 합니다. 평문 `http://`는 루프백 호스트에만 허용됩니다.

내 머신에도 letify가 설치되어 있어야 합니다. 토큰이 서비스 URL을 담고 있으므로 내 머신에서는 URL을 설정하지 않습니다.

---

## 1. 에이전트 시작

에이전트 머신에서:

```bash
letify agent serve --name lab_box
```

내 머신에서 실행할 로그인 명령이 출력됩니다.

```
On your own machine, within 15 minutes, run:

  letify login tunnel lab_box --connect letify-agent2:eyJ2Ijoy...
```

`--name`은 그 명령에 들어가는 별칭입니다. 생략하면 letify가 기본 별칭을 고릅니다.

그 명령에 든 토큰의 성질입니다.

| 항목 | 값 |
|---|---|
| 형식 | `letify-agent2:` 뒤에 URL-safe base64 |
| 사용 횟수 | 1회 |
| 유효 시간 | 15분 |
| 잘못된 증명 5회 | 폐기됨 |
| 에이전트 재시작 후 | 무효. 비밀 값이 실행 중인 에이전트의 메모리에만 있기 때문입니다 |

`letify agent serve`를 실행할 때마다 새 토큰이 출력됩니다. 페어링된 머신 목록은 재시작 후에도 남습니다.

에이전트는 계속 실행되며, 이벤트마다 표준 오류에 한 줄씩 로그를 남깁니다. 로그아웃해도 살아 있는 `tmux` 같은 세션에서 실행하세요.

```bash
tmux new -s letify 'letify agent serve'
```

---

## 2. 내 머신 페어링

내 머신에서, 15분 안에, 출력된 명령을 실행합니다.

```bash
letify login tunnel lab_box --connect letify-agent2:eyJ2Ijoy...
```

letify는 이 계정의 키 `~/.letify/accounts/lab_box/link.key`를 만들고, 시그널링 서비스를 거쳐 에이전트에 증명을 보낸 뒤 최대 30초 동안 응답을 기다립니다. 증명은 토큰의 비밀 값과 두 노드 id로 계산한 HMAC입니다. 그래서 비밀 값은 내 머신을 떠나지 않고, 한 에이전트용 증명은 다른 에이전트에서 쓸 수 없습니다.

성공하면 계정에 `kind = "tunnel"`, 에이전트의 노드 id, 서비스 URL이 기록됩니다. 에이전트는 `paired <노드 앞 12자리> (<라벨>)`을 로그에 남기고, 라벨은 내 머신의 `<사용자>@<호스트명>`입니다.

`letify-agent2:`로 시작하지 않는 토큰은 `letify client shell connect`의 기존 Tailcat 경로로 갑니다. 이 가이드는 그 경로를 다루지 않습니다.

---

## 3. 상태가 있는 곳

에이전트 머신의 `~/.letify/agent/`입니다 (`LETIFY_HOME`이 설정되어 있으면 그 아래). 모드 0700으로 만들어집니다.

| 파일 | 내용 |
|---|---|
| `link.key` | 에이전트의 노드 키, 모드 0600. 첫 실행에 만들어집니다. 그룹이나 다른 사용자가 읽을 수 있으면 에이전트가 거부합니다 |
| `paired.json` | 페어링된 머신: 노드 id, 라벨, 시각. 모드 0600 |
| `config.toml` | 선택. `signal = "<URL>"` |

---

## 4. 페어링된 머신 보기와 제거

```bash
letify agent paired
```

페어링된 머신마다 한 줄씩 노드 id, 날짜, 라벨을 출력합니다. 없으면 `no paired nodes`를 출력합니다.

```bash
letify agent unpair <node>
```

`<node>`는 전체 노드 id이거나, 유일하게 정해지는 8자리 이상의 앞부분입니다. 실행 중인 에이전트는 5초 안에 변경을 알아채고, 그 머신의 대화를 (이미 작업이 실행 중이어도) 끝내며, 이후 메시지는 무시합니다. 재시작은 필요 없습니다.

그 머신을 다시 페어링하려면 `letify agent serve`로 새 토큰을 받으세요.

---

## 한계

- 대화가 동시에 실행되는 머신은 최대 4대입니다. `--max-conversations`로 바꿀 수 있습니다. 한도를 넘은 페어링 머신은 `the agent is busy: <n> conversations`를 받습니다.
- 페어링된 머신마다 대화는 최대 1개입니다. 같은 머신의 새 대화는 이전 대화를 끝냅니다. 다만 이미 실행 중인 워커에 넘어간 대화는 끝까지 둡니다.
- 메시지 하나는 최대 4096바이트이고, 시그널링 서비스는 전달되지 않은 메시지를 최대 60초만 보관합니다.
- 페어링되지 않은 머신의 메시지에는 응답도, 시작되는 것도 없습니다.

---

## 시그널링 서비스로 오가는 것

서명된 부트스트랩 줄만 오갑니다. 노드 id, 후보 주소, NAT 종류, letify 버전, 페어링 증명입니다. 작업 내용은 하나도 오가지 않습니다. 이어지는 세션은 두 머신 사이의 별도 암호화 연결입니다.

서비스는 내용에 대해 신뢰하지 않습니다. 메시지를 읽고, 늦추고, 버릴 수 있으므로 수신 쪽이 모든 메시지를 검증하고, 서명이 없거나 오래되었거나 재전송되었거나 다른 노드 앞으로 온 것은 버립니다. 줄은 서명될 뿐 암호화되지 않습니다. 줄에는 비밀 값, 토큰, 키가 들어 있지 않습니다.

에이전트는 메시지가 건네는 명령을 절대 실행하지 않습니다. 자기에게 설치된 letify의 프로그램만 씁니다.

유휴 상태의 에이전트는 반복 폴링이 아니라 서비스로 연결된 WebSocket 하나에서 기다립니다. 소켓이 끊기면 1초 뒤 다시 연결하고, 연속 실패할 때마다 두 배로 늘려 최대 60초까지 기다립니다.

---

## 에이전트 멈추기

SIGTERM이나 Ctrl-C로 멈춥니다. 실행 중인 워커로 넘어가지 않은 대화를 모두 끝내고 종료 코드 0으로 끝납니다.

---

## 문제 해결

| 메시지 | 원인과 대처 |
|---|---|
| `letify-link is not in this wheel` | 사이드카 바이너리가 없습니다. 플랫폼 wheel을 설치하거나 `LETIFY_LINK_BIN`을 지정하세요 |
| `the signalling URL '...' must be https, or http for a loopback host, not ...` | `--signal`, `LETIFY_SIGNAL_URL`, `config.toml`의 `signal`을 고치세요 |
| `that is not a token: it should start with letify-agent2: ...` | 다른 문자열을 붙여 넣었습니다. `letify agent serve`가 출력한 토큰을 쓰세요 |
| `this is a Tailcat token from 'letify client shell connect'; this login needs ...` | 토큰이 틀렸습니다. `letify agent serve`가 출력한 것을 쓰세요 |
| `the token expired; run 'letify agent serve' again for a new one` | 15분이 지났습니다. 다시 실행하세요 |
| `the pairing secret is wrong, used or expired` | 세 원인에 한 문구입니다. 오타, 이미 쓴 토큰, 15분 경과 중 하나입니다. 새 토큰을 받으세요. 내 노드가 15분 안에 5번 거부되면 에이전트는 더 답하지 않습니다 |
| `the agent <앞 12자리> did not answer in 30 s` | 에이전트가 실행 중이 아니거나, 재시작되었거나 (그 토큰은 무효), 서비스에 닿지 못합니다 |
| `tunnel login failed at pairing: ...` / `at token: ...` / `at sidecar: ...` | 실패한 단계 뒤에 이유가 붙습니다 |
| `the signalling service did not answer: ...` | 서비스나 네트워크가 내려가 있습니다. 에이전트는 스스로 재시도합니다 |
| `no paired node starts with <text>` | 앞부분을 `letify agent paired`와 대조하세요 |
| `<n> paired nodes start with <text>; give more of it` | 앞부분이 유일하지 않습니다. 더 길게 쓰세요 |
| `give a node id or a prefix of at least 8 hex characters` | `unpair`에는 8자리 이상이 필요합니다 |
| `cannot read <path>: ...` | `paired.json`을 읽을 수 없습니다. 소유자와 모드를 확인하세요 |

에이전트 로그에 `refused pairing from <앞 12자리>`가 보이면 페어링 시도가 실패한 것입니다. 로그에는 비밀 값, 증명, 토큰이 들어 있지 않습니다.
