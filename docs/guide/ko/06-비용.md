## 세 겹

손으로 내리는 것이 없습니다. 세션을 끝내는 것이 네 가지이고, 그중 선언하는 것은 하나뿐입니다.

**1. 호출.** 호출이 끝나면 그 세션도 끝납니다. 시간이 겹치는 호출끼리는 그 구간을 공유하니,
한꺼번에 모은 호출 6개는 세션을 한 번 열고 마지막 호출이 끝날 때 닫습니다.

```python
@let.function(device=colab.G4, host="remote")
def train(lr): ...

train(lr=1e-4)        # 여기서 세션이 시작되고 여기서 끝납니다
```

**2. `keep_alive` 블록.** `with let.keep_alive():`는 블록이 끝날 때까지 세션을 호출 뒤에도
유지합니다. 이어지는 호출들이 매번 세션 시작 비용을 내지 않게 하려는 것입니다. Colab에서 그 비용은
부팅과 환경 설치라서 몇 분입니다.

```python
@let.function(device=colab.G4, host="remote")
def train(lr): ...

with let.keep_alive():
    train(lr=1e-4)    # 세션 시작
    train(lr=3e-4)    # 같은 세션 재사용
# 여기서 블록이 끝나고 유휴 세션도 끝납니다
```

device와 환경이 같은 선언 두 개는 어느 쪽이든 세션을 공유합니다. 풀이 그 조합으로 키를 잡고,
어느 함수가 요청했는지는 보지 않기 때문입니다.

타이머로 세션을 끝내는 것은 없습니다. 블록에는 눈에 보이는 끝이 있고, 그 끝이 블록이 유지한 세션을
닫습니다. 블록은 중첩할 수 있고, 가장 바깥 블록이 끝날 때만 세션이 끝납니다.

유지 중인 유휴 세션도 카드를 계속 잡고 있습니다. 블록 안에서 같은 카드를 다른 환경으로 요청하면
기다리지 않고 `letify.InsufficientDevices`가 발생합니다. [문제 해결](07-문제-해결.md)을 보세요.

**3. 리스.** 세션이 기한을 들고 있고 내 프로세스가 30초마다 갱신합니다. 기한이 지나면 워커가 스스로
나갑니다. 유예 300초라서 회선이 불안정한 것으로 학습이 죽지는 않습니다. 이것은 다른 무엇도 덮지 못하는
한 가지 경우를 위한 것입니다. `kill -9`, OOM 킬러, 정전은 코드를 한 줄도 실행하지 않으므로, 부탁받을
때만 끝나는 세션은 끝내 부탁받지 못합니다.

**이것이 사주는 것과 사주지 못하는 것.** 워커가 나가면 카드 점유가 풀립니다. 남의 플랫폼이 과금하고 있는
머신을 끄지는 못합니다. 인프라가 스스로 끝나는 선택을 할 수는 없고, 그것을 소유한 쪽이 꺼야 합니다.

| 프로바이더 | 돈이 나가는 대상 | 내 머신이 강제 종료되면 |
|---|---|---|
| `local` | 없음 | 서브프로세스가 부모와 함께 죽음 |
| `shell`, `tunnel` | 없음. 카드가 점유될 뿐 | 워커가 나가고 카드가 풀림 |
| `modal` | 샌드박스 | **처리됨.** 생성 시 letify가 시한을 걸고 Modal이 집행 |
| `colab` | 런타임 | 처리 못 함. Colab 자체 유휴 정책이 끝내며 12시간 또는 24시간일 수 있음 |
| `elice` | allocation | **처리 못 함.** 누군가 삭제를 호출할 때까지 과금 |

아래 두 개는 지금 letify가 할 수 있는 것이 없습니다. 다음 실행 때의 고아 정리가 의도한 답이지만 아직
구현되지 않았습니다. 그래서 강제 종료된 머신이 남긴 Elice allocation은 누군가 삭제할 때까지 과금됩니다.
크래시 후에는 프로바이더 콘솔을 확인하세요. 머신이 내려갈 것을 미리 알고 있다면 직접 끄는 것이 맞습니다.

## 분리 실행이 없는 이유

긴 작업을 걸어두고 터미널을 닫고 싶을 수 있습니다. letify는 일부러 그걸 제공하지 않습니다.

분리해서 돌리던 원격이 선점되면, Colab에서는 흔한 일인데, 지켜보는 것 없이 결과까지 잃습니다. 그래서 로컬 프로세스가 소유자로 남고, 지속성은 나보다 오래 사는 세션이 아니라 볼륨의 체크포인트에서 나옵니다.

실질적인 결과는 이렇습니다. **긴 작업에는 내 머신이 깨어 있어야 합니다.** 90분 실험은 괜찮습니다. 밤새 돌리려면 머신을 켜둬야 하고, 재시작이 싸도록 체크포인트를 남겨야 합니다.

## 재시작을 싸게 만들기

체크포인트를 스텝 수가 아니라 시간 간격으로 볼륨에 쓰세요. 그러면 무엇이 세션을 죽여도 최대 한 간격만 잃습니다.

```python
cache = colab.volume("hf-cache")

@let.function(device=colab.G4, host="remote", env=env, volumes=[cache])
def train(lr, run="run-1"):
    # 이 이름의 최신 체크포인트가 있으면 거기서 이어받고
    # N 스텝마다가 아니라 N 분마다 저장합니다
    ...
```

시간 기준 저장은 잃는 양을 벽시계 시간으로 묶어줍니다. 세션이 언제든 사라질 수 있는 상황에서 실제로 신경 쓰는 것이 그것입니다.

## 무엇이 돌고 있는지 보기

```python
let.providers.active        # {'colab_a': ['letify-g4-a1b2c3']}
let.status()                # 상한 대비 개수, 그다음 세션별 한 줄
let.pool.live               # Runtime 객체들
```

```bash
letify status
```

`let.providers.active`는 정작 중요한 질문, 즉 지금 돈이 나가고 있느냐에 대한 가장 빠른 답입니다.

## 비용 감각

달러당 1,343원 기준 대략적인 시간당 요금이고, 계획용입니다. 의지하기 전에 현재 가격을 확인하세요.

| GPU | Colab 크레딧 | Modal | 엘리스 |
|---|---|---|---|
| RTX PRO 6000, `G4` | 약 975원 | 약 4,070원 | 없음 |
| H100 80GB | 약 1,340~1,680원 | 약 5,300원 | 5,500원 |
| A100 80GB | 약 841원 | 약 3,360원 | 2,500원 |
| L4 | 약 191원 | 약 1,070원 | 없음 |
| T4 | 약 133원 | 약 790원 | 없음 |

Colab 수치는 49.99달러 600 크레딧 팩 기준으로 크레딧당 약 0.083달러입니다. 크레딧 소모율은 수요에 따라 바뀌니 실제 세션의 리소스 패널에서 확인하세요.

### 놓치기 쉬운 배수

**Modal.** 리전을 지정하면 기본가의 1.15~1.75배, 선점 불가 실행은 3배입니다. 선점 불가 RTX PRO 6000은 시간당 4,070원이 아니라 약 12,000원입니다.

**Colab.** 런타임이 붙어 있으면 코드를 돌리지 않아도 크레딧이 소모됩니다. 세션을 열어두고 코드를 고치는 시간도 과금됩니다.

**엘리스.** 블록 스토리지는 머신이 정지된 동안에도 계속 과금되고, 머신을 지우면 사라집니다. 잊은 머신은 allocation이 없어도 돈이 나갑니다.

**클라우드 스토리지.** 버킷은 저장 용량, 요청 수, 그리고 리전을 잘못 잡으면 리전 간 전송에 요금을 매깁니다. 100GB는 월 몇 천 원인데, 리전 설정이 잘못되면 전송료가 그보다 더 나올 수 있습니다. 멀티리전 버킷을 쓰고 결제 알림을 걸어두세요.

## 실제로 돈이 남는 습관

**유휴 타임아웃을 짧게.** 작업과 생각이 번갈아 오는 패턴이면 600초보다 300초가 낫습니다.

**볼륨을 쓰세요.** 20GB 캐시를 먼 원본에서 27분 걸려 받는 대신 가까운 버킷에서 60초에 받는 것을, 매 세션마다. 지금 할 수 있는 가장 큰 절약입니다.

**작업에 맞는 GPU를 고르세요.** L4는 A100 80GB의 5분의 1 가격입니다. 22GB에 들어가면, 배치를 줄인 하이퍼파라미터 탐색은 흔히 들어가고, 청구서에서 바로 배수가 빠집니다.

**평가를 배치로.** 100발화를 배치 1로 평가하면 250초, 배치 64로 하면 5~10초입니다. 500스텝마다 평가한다면 학습 비용이 두 배가 되는 것과 3% 늘어나는 것의 차이입니다.

**크레딧을 신청하세요.** Modal은 최대 1만 달러의 학술 크레딧이 있습니다. 신청서에 반나절 쓰는 것이 예산 안에서 몇 주 최적화하는 것보다 기대값이 높고, 승인되면 비용 문제 자체가 사라집니다. 지도교수님께 후원을 요청하세요.

**순번 밀린 연구실 GPU를 포기하지 마세요.** 밀려 있어도 공짜입니다. 긴 작업은 순번에 걸어두고, 유료 크레딧은 지금 봐야 하는 것에만 쓰세요.

## 쓰기 전에 확인하기

```bash
letify probe gpu.lab.example.edu     # 왕복, 그리고 중계가 쓸 만한지
letify login shell lab_a100          # 돈을 쓰기 전에 머신을 먼저 등록
letify usage                         # 계정마다 남은 사용량
letify utilization                   # 선언된 GPU가 지금 얼마나 바쁜가
letify check lab_a100                # 머신이 응답하나?
letify devices                          # 각 프로바이더가 제공하는 것
```

`letify usage`는 계정마다 블록 하나를 출력합니다. 한도를 알면 게이지가 나옵니다:

```
modal  modal
  [██████████████████░░░░░░░░░░░░░░░░░░░░░░] 45% used
  $16.50 left of $30.00
  resets in 16 d 18 h (2026-10-01 00:00 UTC)
```

새 프로바이더라면 먼저 아주 간단한 함수 하나를 돌리세요. torch 버전과 장치 이름을 돌려주는 `check` 선언은 몇 초면 되고, 긴 작업을 맡기기 전에 전체 경로를 확인해줍니다.

```python
@let.function(device=colab.G4, host="remote")
def check():
    import torch

    return torch.cuda.get_device_name(0), torch.cuda.get_device_capability(0)
```
