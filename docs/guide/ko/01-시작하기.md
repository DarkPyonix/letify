## 설치

```bash
uv add "letify[colab]"
```

돌리려는 곳에 맞는 extra를 고르세요. `colab`, `modal`, SSH 머신용 `shell`, 또는 `all`입니다.

이 가이드를 따라가는 데 프로바이더가 꼭 필요한 것은 아닙니다. `local` 프로바이더는 항상 있으니, 먼저 내 컴퓨터에서 전체 흐름을 확인할 수 있습니다.

## 계정 없이 먼저 해보기

```python
import letify

let = letify.Launcher()

@let.function(device=let.providers.local.CPU, host="remote")
def add(a, b):
    return a + b

print(add(a=2, b=3))      # 5
```

이미 실제 경로를 지나갔습니다. 함수가 직렬화되어 별도 프로세스로 보내지고, 드라이버 스크립트 아래에서 실행되고, 결과가 디코드되었습니다. 빠진 것은 거리뿐입니다.

## 계정 선언하기

계정은 `~/.letify`에 둡니다. 저장소가 아니라 머신에 속하는 정보이기 때문입니다.

```toml
[colab_a]
kind = "colab"
account = "you@example.com"
```

연구실 서버라면 이렇게 씁니다.

```toml
[lab_a100]
kind = "shell"
address = "gpu.lab.example.edu"
user = "researcher"
key = "~/.ssh/id_ed25519"
```

> 🔐 Git이 추적하는 파일에는 절대 토큰을 직접 쓰지 마세요. 환경 변수를 가리키려면 `access_token_env = "MY_TOKEN"`, OS 키링을 쓰려면 `access_token_keyring = "service/user"`를 씁니다.

여기서 `colab_a` 같은 alias는 파이썬 식별자여야 합니다. 프로바이더를 속성으로 접근하기 때문입니다. `colab-a`는 `colab_a`로 바꾸라는 메시지와 함께 거부됩니다.

## 첫 원격 함수

```python
import letify

let = letify.Launcher()
colab = let.providers.colab_a

@let.function(device=colab.G4, host="remote")
def check():
    import torch

    return {
        "torch": torch.__version__,
        "cuda": torch.version.cuda,
        "device": torch.cuda.get_device_name(0),
        "capability": torch.cuda.get_device_capability(0),
    }

print(check())
```

`capability`가 `(12, 0)`으로 나오면 블랙웰 카드이고, `G4`가 바로 그것입니다. NVFP4가 될 거라고 전제하기 전에 이걸 먼저 확인하세요.

## 환경 붙이기

`Env`는 `uv.lock`을 읽습니다. lock 파일은 모든 플랫폼에 대해 해석되므로, Windows나 macOS 클라이언트에서 하나의 lock 파일로 Linux 런타임을 구성할 수 있습니다.

```python
env = letify.Env()                        # uv.lock
env = env.pip_install("flash-attn")       # lock 파일에 없는 것
env = env.vars(HF_HOME="/opt/cache")      # 런타임의 환경 변수

@let.function(device=colab.G4, host="remote", env=env)
def train(lr, bs): ...
```

## 캐시를 붙여서 재시작을 싸게 만들기

짧은 세션을 쓸 만하게 만드는 가장 큰 변화입니다.

```python
cache = colab.volume("hf-cache")

@let.function(device=colab.G4, host="remote", env=env, volumes=[cache])
def train(lr, bs): ...
```

20GB 모델 캐시를 연구실 서버에서 100Mbps로 받으면 27분, 런타임 옆 버킷에서 받으면 40~60초입니다. 그 시간이 전부 GPU 크레딧으로 청구됩니다. [환경과 데이터](04-환경과-데이터.md)를 보세요.

## 여러 설정 돌리기

```python
@let.function(device=colab.G4, host="remote", env=env, concurrency=3)
async def train(lr, bs):
    ...
    return {"lr": lr, "bs": bs, "loss": loss}

async def main():
    async for result in train(letify.grid(lr=[1e-4, 3e-4, 1e-3], bs=[16, 32])):
        print(result)

asyncio.run(main())
```

`concurrency=3`은 이 선언이 런타임 세 개를 동시에 쓸 수 있다는 뜻입니다. 6개 조합을 세 런타임에 나누면 벽시계 시간이 약 3분의 1이 됩니다. [스윕과 병렬 실행](05-스윕.md)을 보세요.

## 더 가기 전에 알아둘 것

**호출을 무엇으로도 감쌀 필요가 없습니다.** 호출할 때 세션이 시작되고 호출이 끝나면 세션도 끝나니, 열 스코프도 내릴 것도 없습니다. 여러 호출이 한 세션을 공유해야 할 때만 `lifetime="process"`를 선언하세요.

**스크립트가 살아 있어야 합니다.** 분리 실행 모드는 없습니다. 로컬 프로세스가 종료되면 원격 세션은 리스 유예 시간 안에 스스로 종료합니다. 긴 작업이라면 볼륨에 체크포인트를 써서 재시작이 이어지게 하세요. [비용 관리](06-비용.md)를 보세요.

**Colab은 GPU를 쓰려면 유료 플랜이 필요하고**, letify가 쓰는 원격 제어 기능은 컴퓨트 유닛 잔액이 남아 있는 동안 허용됩니다.
